Atlas explicativo

Sistema Experto de SmartMarket SV

Referencia completa de cómo el motor de reglas en Python conversa con Laravel y React: qué datos cruzan cada frontera, cómo se decide una recomendación, y cómo se explica al usuario final. Construido con evidencia real capturada contra el servicio desplegado — no diagramas especulativos.

Cómo leer este atlas: cada sección es independiente — usa la navegación lateral para saltar directo a lo que necesitas. Los bloques de código muestran JSON real, capturado con Http::record() contra llamadas HTTP reales, no ejemplos inventados
↔ Desplaza · Flujo usuario → React → Laravel → Python
Conocimiento · 01

Los 13 hechos del contrato

Cada alternativa de compra evaluada se traduce a estos campos antes de cruzar hacia Python. Nunca viajan datos crudos de negocio: sin SQL, sin nombres de producto, sin precios individuales por artículo.

HechoTipoDescripción
costo_totalfloatCosto total de la compra en esa alternativa
presupuestofloatPresupuesto definido por el usuario
ahorrofloatmax(0, costo_referencia − costo_total) — costo_referencia es el costo máximo entre alternativas válidas de la misma consulta
distancia_kmfloatDistancia del usuario a la sucursal
distancia_adicional_kmfloatmax(0, distancia_actual − distancia_mínima) sobre el conjunto de alternativas válidas
tiempo_estimado_minfloat ≥ 0Tiempo estimado de trayecto
productos_disponibles / _totalesintDisponibilidad general de la lista
productos_esenciales_disponibles / _totalesintDisponibilidad específica de productos esenciales
numero_supermercadosintSupermercados que esa alternativa específica requiere — no el total del conjunto comparado (ver Caso: defecto detectado)
promociones_aplicablesboolbeneficio_promociones > 0
Nunca se envían a Python: score, penalizacion_distancia, costo_tiempo, costo_combustible, tipo_vehiculo, km_por_litro, precio_por_litro, latitud/longitud. Variables no verificables con precisión razonable (ADR-05) quedan fuera del contrato por diseño.
Conocimiento · 02

Hechos derivados y umbrales

Antes de evaluar reglas, el motor deriva más de 25 condiciones booleanas a partir de los 13 hechos de entrada.

Presupuesto

muy_excedido si el exceso supera 10%

Ahorro

bajo < $3.00 · alto ≥ $10.00

Distancia

cercana ≤ 2 km adicionales · lejana ≥ 8 km

Tiempo

bajo ≤ 20 min · alto ≥ 45 min

Fragmentación

compra_fragmentada si ≥ 3 supermercados en la misma alternativa

Paradas

una_parada · dos_paradas · compra_fragmentada

Conocimiento · 03

Catálogo de 8 reglas

Organizadas en 8 categorías de prioridad — 1 es la más crítica. La resolución de conflictos se explica en la siguiente sección.

IDCategoría (prioridad)CondiciónNivel
R01PRESUPUESTO (1)presupuesto_muy_excedidoNO_RECOMENDABLE
R02DISPONIBILIDAD (2)faltan_esencialesNO_RECOMENDABLE
R03DISTANCIA_AHORRO (3)distancia_lejana AND ahorro_bajoNO_RECOMENDABLE
R04TIEMPO_AHORRO (3)tiempo_alto AND ahorro_bajoNO_RECOMENDABLE
R05 *FRAGMENTACION (4)compra_fragmentada (3+ tiendas)NO_RECOMENDABLE
R06CONVENIENCIA (5)presupuesto + esenciales + cercana + rápida + 1 paradaEXCELENTE
R08 *AHORRO_FRAGMENTACION (5)2 paradas AND ahorro_alto AND presupuestoBUENA
R07PROMOCIONES (6)presupuesto + esenciales + promo relevanteBUENA
* R05 y R08 requieren que una alternativa combine 2+ supermercados ("compra dividida"). Esta funcionalidad no existe hoy del lado de Laravel — ver Limitaciones.
Motor · 04

Pipeline de inferencia

Motor propio en Python puro — sin PyKnow, CLIPS ni Durable Rules. Cinco etapas, deterministas de principio a fin.

derive_facts → load_rules → evaluación AND estricta (con trace) → resolve_conflicts → build_inference_result → enrich_inference_result

Motor · 05

Resolución de conflictos

Reglas del motor

① Gana la regla activada con menor número de prioridad (1 = más crítica).

② En empate, gana el ID ascendente menor (R03 antes que R04).

③ El proceso es 100% determinista — misma entrada, misma salida.

④ Sin regla activa → NO_RECOMENDABLE provisional.

Ejemplo real

Faltan esenciales en la lista:

R02 · DISPONIBILIDAD (2) — GANA
R05 · FRAGMENTACION (4) — evaluada, no activada

Prioridad 2 < Prioridad 4 → R02 decide, aunque otras reglas también se evalúen.

Comunicación · 09

Indisponibilidad y fallback

El backend Laravel nunca bloquea al usuario si el Sistema Experto no responde.

⏱️ Timeout

3 segundos por intento

🔁 Reintentos

2 intentos totales, espera fija de 500ms

🛟 Fallback

Siempre HTTP 200 hacia React

Respuesta cuando se omite la llamada (presupuesto/distancia/tiempo nulos, o falla el servicio)
{
  "recommendation": null,
  "expert_system_available": false
}
Regla estricta: nunca se envían valores artificiales (como 0) para campos desconocidos, y nunca se envía null a Python en campos obligatorios. Si un dato requerido no puede calcularse con un valor real, esa alternativa se omite por completo.

Los campos técnicos (reglas_activadas, trace, winning_rule, códigos R0x) se ocultan de la vista pública. El usuario final solo ve nivel_recomendacion, accion_sugerida, explicacion, y el índice de conveniencia.

Explicabilidad · 12

Caso de estudio: un defecto real, detectado y corregido

numero_supermercados se calculaba sobre todo el conjunto comparado, no por alternativa individual — causando activación espuria de R05.

ANTES

Dos sucursales del mismo supermercado (Súper Selectos) recibían:

"compra_fragmentada": true

→ R05 se activaba de forma espuria, aunque comprar en una sola tienda nunca puede ser una "compra fragmentada".

DESPUÉS

Misma corrida, re-ejecutada tras el fix:

Súper Selectos → R06 EXCELENTE
Walmart → R07 BUENA

R05: evaluada en ambas, NO activada

Fragmento real del trace devuelto por Python (post-fix)
{
  "rule_id": "R05",
  "evaluated": true,
  "activated": false,
  "conditions": {
    "compra_fragmentada": {
      "expected": true,
      "actual": false,
      "matched": false
    }
  },
  "matched_conditions": [],
  "unmatched_conditions": [
    "compra_fragmentada"
  ],
  "reason": "Una o más condiciones no se cumplieron."
}

Verificado con evidencia empírica contrastada — antes y después de la corrección — reforzando la disciplina de verificación que el equipo mantiene en todo el proyecto.

Cierre · 13

Limitaciones y trabajo futuro

R05 / R08 pendientes

Listas y probadas del lado de Python; requieren "compra dividida", aún no implementada en Laravel.

Chatbot sin estado

No mantiene contexto entre preguntas de una misma conversación (decisión deliberada del MVP).

Hosting gratuito

Cold-start de 30–50s en Render — mitigado con timeout y fallback, no eliminado.

Catálogo de reglas inicial

Se planea ampliar el conjunto de reglas para cubrir más escenarios de decisión.
